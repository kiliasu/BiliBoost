# BiliBoost

一款 Tampermonkey 用户脚本，让哔哩哔哩在海外网络下也能正常播放。

## 问题所在

以下结论来自 2026 年 7 月在中国大陆以外进行的测试，共抽取了 12 个视频：

- CDN 节点的表现取决于该节点的边缘缓存中是否已有目标视频，这取决于视频的热门程度。热门视频通过哔哩哔哩分配的海外节点可以达到 40–500 Mbps；冷门视频则可能在主节点和备用节点上都请求超时，最终导致播放器放弃加载。
- 部分Github中的工具采用替换CDN进行优化，但对于高码率视频并无帮助。
- 跨境线路会把单条 TCP 连接限制在约 1.4–2.3 Mbps。更换节点无法绕过单连接限速，但同时向多个节点发起并行范围请求可以；测试中速度提升了 3–15 倍。
- 中国大陆的镜像节点能稳定提供热门和冷门内容。只需替换主机名，任意 `bilivideo.com` 节点都可以正常工作。`akamaized.net` 使用另一套签名机制：将其他 URL 改写到该域名会返回 403，但哔哩哔哩原生分配的 URL 可以正常播放。
- 在实测中，未安装脚本时最多可以支持1080p（非高码率）的正常播放，安装后对于任意视频皆可流畅播放（4K，冷源视频）

## 脚本做了什么

- 针对每个视频探测多个候选节点，分别采样文件开头和靠后的一个位置，再选择表现最好的节点。只采样文件开头会漏掉那些仅缓存了前几 MB 的节点。
- 把较大的媒体请求拆成多个分片，同时从多个节点下载。每个分片都有超时监控；某个节点缺失的分片会由其他节点补齐。实测速度为 22–103 Mbps，而单连接约为 2 Mbps；其中一个问题视频的起播时间从 37 秒缩短到了 251 毫秒。
- 遇到缓存未命中时，按候选节点顺序依次回退；同时在后台预热首选节点，并在播放卡住时强制切换节点。
- 通过由媒体播放状态驱动的心跳机制，让后台标签页继续维持缓冲；切回页面时不必重新等待加载。
- 提供一个悬浮面板，可查看实时吞吐量和各节点的健康状态，也可以运行测速并导出诊断报告。

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/)。
2. 导入 `bilibili-cdn-optimizer.user.js`。


支持 `/video/*`、`/bangumi/play/*`、`/list/*`、`/festival/*` 和 `/watchlater/*`。设置保存在 `localStorage` 中，可通过悬浮面板修改。

## 限制

- 脚本可能在未来失效。
- 2026-8-12 验证可用。
